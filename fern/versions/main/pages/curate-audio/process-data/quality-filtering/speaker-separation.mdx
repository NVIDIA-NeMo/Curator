# Speaker Separation

Diarize multi-speaker audio and either fan out one task per detected speaker or
retain whole-recording diarization metadata. NeMo Curator ships **two** stages
built on NVIDIA's [SortFormer](https://huggingface.co/nvidia/diar_sortformer_4spk-v1)
family. Both target up to 4 speakers per file; choose based on the output
contract your downstream pipeline needs.

## Understanding Diarization

### What Diarization Does

Diarization answers "who spoke when?" — it segments an audio stream into
per-speaker regions, identifying that speaker A talks 0.0–3.5s, speaker B
talks 3.5–7.0s, speaker A returns at 7.0–9.0s, and so on.
`SpeakerSeparationStage` emits one `AudioTask` **per speaker**, each containing
only that speaker's audio. `InferenceSortformerStage` instead retains one task
per recording and adds diarization intervals and speaker count metadata.

This unlocks **per-speaker filtering**: pipelines can rerun VAD, UTMOS, SIGMOS, and the band filter separately on each speaker, dropping individual low-quality speakers without losing the rest of the recording.

### Choosing a Stage

| Stage | Model | Best For |
|-------|-------|----------|
| `SpeakerSeparationStage` | `nvidia/diar_sortformer_4spk-v1` (offline) | Bulk offline curation. Used inside `AudioDataFilterStage`. Higher accuracy because it sees the whole utterance. |
| `InferenceSortformerStage` | `nvidia/diar_streaming_sortformer_4spk-v2.1` | Whole-recording diarization metadata and optional RTTM output. The checkpoint uses streaming inference internally. |

Use `SpeakerSeparationStage` when downstream filters need per-speaker
waveforms. Use `InferenceSortformerStage` when a manifest should retain one
row per recording with diarization intervals, speaker count, or RTTM output.

## Offline Speaker Separation

### Step 1: Configure the Stage

```python
from nemo_curator.stages.audio.segmentation.speaker_separation import SpeakerSeparationStage

speaker_sep = SpeakerSeparationStage(
    model_path="nvidia/diar_sortformer_4spk-v1",
    exclude_overlaps=True,
    min_duration=0.8,
    gap_threshold=0.1,
    buffer_time=0.5,
)
pipeline.add_stage(speaker_sep)
```

The stage produces a fan-out list of `AudioTask` objects, one per detected speaker, each carrying:

- `speaker_id` — speaker identifier (0, 1, 2, ...)
- `num_speakers` — total speakers found in this file
- `duration` — duration of this speaker's audio in seconds
- `waveform` — that speaker's torch tensor with overlapping regions removed (when `exclude_overlaps=True`)

GPU is required (`Resources(cpus=1.0, gpus=1.0)` by default).

### Step 2: Tune Overlap and Gap Handling

Speaker overlap regions (where multiple speakers talk simultaneously) and short gaps between same-speaker turns affect output quality:

| Parameter | Effect |
|-----------|--------|
| `exclude_overlaps=True` (default) | Drops overlapping regions. Better for clean per-speaker training data. |
| `exclude_overlaps=False` | Includes overlapping regions on each speaker's audio. Useful when you want to preserve natural conversation. |
| `gap_threshold=0.1` (default) | Same-speaker turns separated by < 100 ms are merged. Increase to 0.3–0.5 for more aggressive merging on fragmented diarization. |
| `min_duration=0.8` (default) | Drop speakers whose total audio is shorter than 0.8 seconds. Filters out spurious speaker detections. |
| `buffer_time=0.5` (default) | Buffer (in seconds) added around each merged speaker segment to avoid clipping turn boundaries. |

### `SpeakerSeparationStage` Parameters

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `model_path` | str | `"nvidia/diar_sortformer_4spk-v1"` | Hugging Face model ID or path to a `.nemo` checkpoint. |
| `exclude_overlaps` | bool | `True` | Drop regions where multiple speakers overlap. |
| `min_duration` | float | `0.8` | Minimum per-speaker segment duration (seconds). |
| `gap_threshold` | float | `0.1` | Gap threshold for merging adjacent same-speaker segments. |
| `buffer_time` | float | `0.5` | Buffer (seconds) added around each merged speaker segment. |

## Adapter-Backed Sortformer Diarization

### When to Use It

`InferenceSortformerStage` is purpose-built for two use cases:

1. **Manifest enrichment** — retain each recording as one task and add
   `diar_segments` plus `num_speakers`.
2. **RTTM output** — downstream tooling (Kaldi, ESPnet, evaluation harnesses)
   consumes RTTM-format diarization output.

The Curator stage processes a complete recording. The selected v2.1 model has
streaming parameters internally, but the stage is not a live-stream source
and does not assign globally consistent speakers across independently cut
chunks. For per-speaker waveform fan-out, use `SpeakerSeparationStage`.

### Step 1: Configure the Stage

```python
from nemo_curator.stages.audio.inference.speaker_diarization.stage import InferenceSortformerStage
from nemo_curator.stages.resources import Resources

streaming = InferenceSortformerStage(
    adapter_target=(
        "nemo_curator.models.audio.speaker_diarization.sortformer."
        "NeMoSortformerAdapter"
    ),
    model_id="nvidia/diar_streaming_sortformer_4spk-v2.1",
    rttm_out_dir="./rttm",
    adapter_kwargs={
        "chunk_len": 340,
        "chunk_right_context": 40,
        "inference_batch_size": 1,
        "precision": "fp32",
    },
).with_(resources=Resources(gpus=1), batch_size=4, num_workers=1)
pipeline.add_stage(streaming)
```

The former
`nemo_curator.stages.audio.inference.speaker_diarization.sortformer` import
continues to re-export the stage for compatibility. New code should use the
task-facing `speaker_diarization.stage` module shown above; model adapters live
under `nemo_curator.models.audio.speaker_diarization`. Existing constructor
names (`model_name`, `model_path`, `cache_dir`, `diar_model`, `filepath_key`,
streaming-context fields, and `inference_batch_size`) are translated to the
canonical stage/adapter fields with conflict checks; new configurations should
use `model_id`, `audio_filepath_key`, and `adapter_kwargs` directly.

This stage **does not fan out per speaker** — instead it writes a
`diar_segments` list and `num_speakers` onto the input `AudioTask`. The stage
owns task fields, input-mode selection, in-memory downmix/resampling, RTTM
paths, task-local errors, and resume checks. The adapter owns the checkpoint,
worker-local model state, provider-native path decoding or bounded streaming,
streaming configuration, precision, and inference. Each adapter item contains
exactly one of `audio_filepath` or `waveform` plus `sample_rate`.

### Step 2: Tune the Checkpoint's Streaming Context

`chunk_len` is an adapter setting that controls the model's internal context
trade-off. It does not change the whole-recording task boundary:

| `chunk_len` | Latency | Accuracy |
|-------------|---------|----------|
| 100 (~8 s) | Low | Lower (less context) |
| 340 (default, ~30.4 s) | Medium | Good |
| 600 (~48 s) | High | Best |

Streaming-mode evaluation on **CallHome-eng0** (139 files) at the default settings: **6.2% macro DER**, **6.0% weighted DER** at a 0.25-second collar.

### `InferenceSortformerStage` Parameters

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `adapter_target` | str | `nemo_curator.models.audio.speaker_diarization.sortformer.NeMoSortformerAdapter` | Import path for the diarization adapter. |
| `model_id` | str | `"nvidia/diar_streaming_sortformer_4spk-v2.1"` | Provider model ID passed to the adapter. |
| `audio_filepath_key` | str | `"audio_filepath"` | Manifest key with the audio path. |
| `waveform_key` | str \| None | `None` | In-memory waveform key; leave unset for file input. |
| `sample_rate_key` | str | `"sample_rate"` | Sample-rate key used with an in-memory waveform. |
| `diar_segments_key` | str | `"diar_segments"` | Output manifest key for the diarization segment list. |
| `num_speakers_key` | str | `"num_speakers"` | Output key for the number of distinct speakers. |
| `store_segments` | bool | `True` | Store JSON-safe intervals on the task. Set to `False` only when RTTM output is enabled. |
| `rttm_out_dir` | str \| None | `None` | Exact root directory for per-recording RTTM files. Sharded tasks retain their shard subdirectory below it. |
| `skip_if_output_exists` | bool | `False` | Reuse output by key presence. An empty interval list is complete; with RTTM enabled, the referenced file must also resolve safely below `rttm_out_dir` and exist. |
| `adapter_kwargs` | dict | `{}` | Provider settings such as a local `model_path`, `cache_dir`, streaming context, precision, or bounded-STFT controls. |

Default resource allocation is `Resources(cpus=1.0, gpu_memory_gb=8.0)`.
Override executor controls with `.with_(resources=..., batch_size=...,
num_workers=...)`; do not place them in `adapter_kwargs`.

Independent recordings in one stage batch may be duration-sorted for the
adapter call and are scattered back to input order. Never split one recording
merely to improve batching: global speaker clustering and speaker identity
make arbitrary chunks non-equivalent.

### Select the TensorRT Adapter

The same task-facing stage can host a target-specific TensorRT Sortformer
engine. Supply all deployment artifacts explicitly:

```bash
uv sync --extra audio_cuda12 --extra audio_tensorrt
```

```python
tensorrt_diarization = InferenceSortformerStage(
    adapter_target=(
        "nemo_curator.models.audio.speaker_diarization.sortformer_tensorrt."
        "TensorRTSortformerAdapter"
    ),
    model_id="nvidia/diar_streaming_sortformer_4spk-v2.1",
    adapter_kwargs={
        "engine_path": "/models/sortformer.plan",
        "config_path": "/models/sortformer.json",
        "runtime_module_path": "/models/sortformer.sortformer_modules.py",
        "inference_batch_size": 4,
    },
).with_(resources=Resources(gpus=1), batch_size=4)
```

Build the bundle from a local `.nemo` checkpoint on the target GPU:

```bash
python -m nemo_curator.models.audio.speaker_diarization.build_sortformer_tensorrt_engine \
  --nemo-model /models/sortformer.nemo \
  --runtime-module /opt/riva/backends/sortformer_modules.py \
  --output /models/sortformer.plan
```

The builder validates a staged bundle before publishing the config last. It
writes `/models/sortformer.plan`, `/models/sortformer.json`,
`/models/sortformer.mel_basis.npy`,
`/models/sortformer.sortformer_modules.py`, and, when the checkpoint uses it,
`/models/sortformer.learnable_sil_emb.npy`. TensorRT engines are
target-specific, so build on the same GPU architecture used for deployment.

`engine_path`, `config_path`, and `runtime_module_path` are required adapter
settings. The runtime module is executable Python and must come from a trusted
conversion/deployment environment. Optional TensorRT controls include
`speech_threshold`, `long_audio_seconds`, and `stft_block_seconds`. Engine
profiles and the stage batch size must be compatible. Switching adapters does
not change `diar_segments`, `num_speakers`, RTTM, error, or resume semantics.
TensorRT uses bounded waveform reads and STFT calls for long same-rate file
inputs. The full-recording normalized feature matrix and output probabilities
still grow with duration. Regular files and in-memory waveforms may be
materialized, and long files that require resampling are rejected rather than
silently materializing a second full waveform.
The schema-v2 runtime JSON also freezes the checkpoint's frontend
normalization. Older or ambiguous configs are rejected; rebuild those bundles
so TensorRT receives the same normalized features as NeMo.

## Complete Speaker Separation Pipeline

A pipeline that diarizes, then runs per-speaker quality filters:

```python
from nemo_curator.pipeline import Pipeline
from nemo_curator.backends.xenna import XennaExecutor
from nemo_curator.stages.audio.preprocessing.mono_conversion import MonoConversionStage
from nemo_curator.stages.audio.segmentation.vad_segmentation import VADSegmentationStage
from nemo_curator.stages.audio.preprocessing.concatenation import SegmentConcatenationStage
from nemo_curator.stages.audio.segmentation.speaker_separation import SpeakerSeparationStage
from nemo_curator.stages.audio.filtering.utmos import UTMOSFilterStage
from nemo_curator.stages.audio.postprocessing.timestamp_mapper import TimestampMapperStage
from nemo_curator.stages.audio.io.convert import AudioToDocumentStage
from nemo_curator.stages.text.io.writer import JsonlWriter

pipeline = Pipeline(name="speaker_diarization")

# 1. Normalize and segment
pipeline.add_stage(MonoConversionStage(output_sample_rate=48000))
pipeline.add_stage(VADSegmentationStage(min_duration_sec=2.0, nested=True))

# 2. Concatenate surviving segments per file
pipeline.add_stage(SegmentConcatenationStage(silence_duration_sec=0.5))

# 3. Diarize and fan out per speaker
pipeline.add_stage(SpeakerSeparationStage(exclude_overlaps=True))

# 4. Per-speaker quality filter
pipeline.add_stage(UTMOSFilterStage(mos_threshold=3.5))

# 5. Resolve final timestamps
pipeline.add_stage(
    TimestampMapperStage(
        passthrough_keys=["speaker_id", "num_speakers", "utmos_mos"]
    )
)

# 6. Export
pipeline.add_stage(AudioToDocumentStage())
pipeline.add_stage(JsonlWriter(path="./per_speaker_audio"))

executor = XennaExecutor()
pipeline.run(executor)
```

## Best Practices

- **Choose by output contract**: use `SpeakerSeparationStage` for per-speaker
  waveform fan-out and `InferenceSortformerStage` for whole-recording segment
  metadata or RTTM files.
- **Run VAD + concat before diarization**: feeding diarization a clean concatenated speech-only waveform (no long silences) is cheaper and more reliable than feeding raw audio.
- **Pair with per-speaker quality filters**: place the filtering chain (VAD → Band → UTMOS → SIGMOS) **after** speaker separation so each speaker's audio is scored independently. Bad speakers get dropped; good speakers from the same file are kept.
- **Mind the 4-speaker model limit**: both stages target up to 4 speakers per file. Files with more speakers will likely produce degraded diarization.
- **Keep each diarization item whole**: batching independent recordings is
  safe; arbitrarily segmenting one recording before diarization can change
  clustering and speaker labels.
- **Don't enable `exclude_overlaps=False` for training data**: overlapping speech is hard for downstream models; only disable when explicitly preserving natural conversation.
