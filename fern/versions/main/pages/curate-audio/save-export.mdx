# Save & Export Audio Data

Export processed audio data and transcriptions in formats optimized for ASR model training, audio-and-text applications, and downstream analysis workflows.

## Output Formats

NeMo Curator's audio curation pipeline supports several output formats tailored for different use cases:

### JSONL Manifests

The primary output format for audio curation is JSONL (JSON Lines):

```json
{"audio_filepath": "/data/audio/sample_001.wav", "text": "hello world", "pred_text": "hello world", "wer": 0.0, "duration": 2.1}
{"audio_filepath": "/data/audio/sample_002.wav", "text": "good morning", "pred_text": "good morning", "wer": 0.0, "duration": 1.8}
```

### Metadata Fields

Standard fields included in audio manifests:

| Field | Type | Description |
|-------|------|-------------|
| `audio_filepath` | string | Absolute path to audio file |
| `text` | string | Ground truth transcription |
| `pred_text` | string | ASR model prediction |
| `wer` | float | Word Error Rate percentage |
| `duration` | float | Audio duration in seconds |
| `language` | string | Language identifier (optional) |

## Export Configuration

### Manifest writer with a terminal performance summary

`ManifestWriterStage` writes an audio JSONL manifest directly and can also
emit one terminal `perf_summary.json` after a successful pipeline run,
including a run where every row is filtered:

```python
from nemo_curator.stages.audio.common import ManifestReader, ManifestWriterStage

pipeline.add_stage(
    ManifestReader(
        manifest_path="/input/audio.jsonl",
        duration_key="duration",
    )
)
pipeline.add_stage(
    ManifestWriterStage(
        output_path="/output/audio.jsonl",
        write_perf_stats=True,
        duration_key="duration",
        perf_summary_path="/output/perf_summary.json",
        perf_run_id="run-2026-07-29",
        perf_executor="RayDataExecutor",
        perf_pipeline_metadata={"pipeline": "qwen-omni"},
    )
)
```

| Option | Default | Description |
|---|---|---|
| `write_perf_stats` | `False` | Enable the terminal summary. |
| `duration_key` | `"duration"` | Input and output field containing audio seconds. Set the same value on `ManifestReader` and `ManifestWriterStage` for a custom field. |
| `perf_summary_path` | `None` | Explicit artifact path. When omitted, the file is named `perf_summary.json` beside `output_path`. |
| `perf_run_id` | `""` | Caller-owned run ID. A `Pipeline` generates one when blank. |
| `perf_executor` | `""` | Caller-owned executor label. A `Pipeline` uses the executor class name when blank. |
| `perf_pipeline_metadata` | `None` | Additional JSON-serializable metadata copied into the artifact. |

The artifact contains run and executor identity, pipeline wall time,
input/output row and duration coverage, manifest-write timing, and a `stages`
mapping keyed by stable execution-plan IDs. Stage entries contain process
totals, invocation counts, custom metric sums, and derived throughput.
Actor/GPU identity and hardware-derived fields are optional and appear only
when the selected backend provides them.

`input_hours` or `output_hours` is JSON `null` if any row at that boundary
lacks a finite, non-negative value under `duration_key`; this prevents a
partial total from looking complete. A successful empty boundary is measured
and reported as `0`. Ray Data and Xenna retain all-filtered invocations through
driver-owned telemetry, so their process time and filter counters remain in a
zero-output summary.

For distributed runs, `output_path` and `perf_summary_path` must resolve to
storage visible to the workers and driver. Summary collection is fail-open:
unavailable optional telemetry is omitted rather than failing manifest
export. The schema is additive, so consumers should ignore unknown fields.

`perf_pipeline_metadata` is serialized exactly as supplied and is not
redacted. Do not put credentials, access tokens, private prompts, or other
secrets in it. See [Monitoring](/reference/infra/monitoring) for the
difference between this terminal artifact and live Prometheus/Grafana
monitoring. The
[Qwen-Omni tutorial](https://github.com/NVIDIA-NeMo/Curator/tree/main/tutorials/audio/qwen_omni_inprocess)
is a concrete consumer of the summary.

## Directory Structure

### Standard Output Layout

When `source_files` metadata exists, the writer generates deterministic hashed file names. Otherwise, it generates UUID-based names.

```text
/output/audio_manifests/
├── <hash>.jsonl   # Deterministic hash if metadata.source_files present, else UUID
├── <hash>.jsonl
└── ...
```

## Quality Control

### Validation Checks

Before export, check your processed data:

```python
from nemo_curator.stages.audio.common import PreserveByValueStage

# Filter by quality thresholds
quality_filters = [
    # Keep samples with WER &lt;= 50%
    PreserveByValueStage(
        input_value_key="wer",
        target_value=50.0,
        operator="le"
    ),
    # Keep samples with duration 1-30 seconds
    PreserveByValueStage(
        input_value_key="duration", 
        target_value=1.0,
        operator="ge"
    ),
    PreserveByValueStage(
        input_value_key="duration",
        target_value=30.0, 
        operator="le"
    )
]

for filter_stage in quality_filters:
    pipeline.add_stage(filter_stage)
```
