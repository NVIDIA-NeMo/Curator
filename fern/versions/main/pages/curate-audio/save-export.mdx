# Save & Export Audio Data

Export processed audio data and transcriptions in formats optimized for ASR model training, audio-and-text applications, and downstream analysis workflows.

## Output Formats

NeMo Curator's audio curation pipeline supports several output formats tailored for different use cases:

### JSONL Manifests

The primary output format for audio curation is JSONL (JSON Lines):

```json
{"audio_filepath": "/data/audio/sample_001.wav", "text": "hello world", "pred_text": "hello world", "wer": 0.0, "duration": 2.1}
{"audio_filepath": "/data/audio/sample_002.wav", "text": "good morning", "pred_text": "good morning", "wer": 0.0, "duration": 1.8}
```

### Metadata Fields

Standard fields included in audio manifests:

| Field | Type | Description |
|-------|------|-------------|
| `audio_filepath` | string | Absolute path to audio file |
| `text` | string | Ground truth transcription |
| `pred_text` | string | ASR model prediction |
| `wer` | float | Word Error Rate percentage |
| `duration` | float | Audio duration in seconds |
| `language` | string | Language identifier (optional) |

## Export Configuration

### Terminal performance summary

`ManifestWriterStage` can emit one run-level `perf_summary.json` beside the
JSONL manifest:

```python
from nemo_curator.stages.audio.common import ManifestWriterStage

pipeline.add_stage(
    ManifestWriterStage(
        output_path="/output/audio.jsonl",
        write_perf_stats=True,
        duration_key="duration",
        # Defaults to perf_summary.json beside output_path when omitted.
        perf_summary_path="/output/perf_summary.json",
        perf_run_id="run-2026-07-29",
        perf_executor="RayDataExecutor",
        perf_pipeline_metadata={"pipeline": "qwen-omni"},
    )
)
```

The artifact is finalized once during writer teardown, including successful
zero-row runs. It contains run/executor metadata, input/output row and audio
totals, writer timing, and per-stage latency, throughput, actor, and GPU
breakdowns when the corresponding telemetry is available.

`ManifestReaderStage` supplies the input row boundary and sums non-negative,
finite `duration` values from the input manifest. If no source stage supplies
an input boundary, `rows_in` is JSON `null`. If any input row lacks a valid
duration, `input_hours` is `null` rather than a misleading partial total.
`null` means "unavailable" and is distinct from a measured empty input, which
is `0`. The terminal writer always supplies the output boundary, including a
measured zero for a successful empty run.

Stages are keyed by their stable execution-plan ID when supplied, while
`stage_name` remains the display label. This keeps two distinct stages with
the same public name separate. GPU efficiency uses distinct assigned physical
devices, so a tensor-parallel actor using two GPUs contributes two GPU units,
not one actor unit.

For remote output, use a location visible to the terminal writer and driver.
Collection is fail-open: unavailable NVML fields are omitted rather than
failing manifest export. See [Monitoring](/reference/infra/monitoring) for
stage and executor enablement.

`perf_pipeline_metadata` is serialized exactly as supplied. Do not place
credentials, access tokens, private prompts, or other secrets in that mapping.
The summary schema is additive: consumers should ignore unknown fields and
treat omitted optional telemetry as unavailable.

from nemo_curator.stages.audio.common import ManifestWriterStage

pipeline.add_stage(

The writer publishes one run-level performance artifact after successful
pipeline execution. The artifact is also created when the pipeline produces
zero output rows. If `perf_summary_path` is omitted, it is written as
`perf_summary.json` beside `output_path`.

`duration_key` must identify the manifest field containing audio seconds.
Duration-derived fields are `null` when one or more rows do not provide a
valid duration; this distinguishes unavailable measurements from a measured
zero. Planned stages receive stable IDs, so repeated display names remain
separate in the `stages` mapping.

For multi-node execution, both output paths must resolve to shared storage.
Actor and GPU topology fields are best effort and appear only when the backend
provides that identity. Caller-supplied `perf_pipeline_metadata` is serialized
as provided and is not automatically redacted.

## Directory Structure

### Standard Output Layout

When `source_files` metadata exists, the writer generates deterministic hashed file names. Otherwise, it generates UUID-based names.

```text
/output/audio_manifests/
├── <hash>.jsonl   # Deterministic hash if metadata.source_files present, else UUID
├── <hash>.jsonl
└── ...
```

## Quality Control

### Validation Checks

Before export, check your processed data:

```python
from nemo_curator.stages.audio.common import PreserveByValueStage

# Filter by quality thresholds
quality_filters = [
    # Keep samples with WER &lt;= 50%
    PreserveByValueStage(
        input_value_key="wer",
        target_value=50.0,
        operator="le"
    ),
    # Keep samples with duration 1-30 seconds
    PreserveByValueStage(
        input_value_key="duration", 
        target_value=1.0,
        operator="ge"
    ),
    PreserveByValueStage(
        input_value_key="duration",
        target_value=30.0, 
        operator="le"
    )
]

for filter_stage in quality_filters:
    pipeline.add_stage(filter_stage)
```
